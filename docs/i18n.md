# Panel internationalization

The React tray panel and desktop workspace share one locale store. Settings →
Display → Language selects `system`, `zh-CN`, or `en`. The default follows the
first system language: Chinese variants resolve to Simplified Chinese, all other
languages resolve to English. The selected preference is saved under
`quotabar.language` using the existing storage failure reporting.

## Boundaries

- `src/i18n/en.ts` and `src/i18n/zh-CN.ts` own the English and Chinese resources.
  `messages.ts` joins the locale catalogs. English source messages are the stable
  keys; TypeScript checks that Chinese has the same keys. Edit both together.
- `src/i18n/index.ts` owns resolution, persistence, interpolation and stored message
  rendering. `t(key, values)` checks keys and required interpolation parameters at
  compile time. Missing runtime parameters fail explicitly.
- `src/i18n/react.ts` subscribes rendering to the store using `useSyncExternalStore`.
  Components call `useLocale()`; changing language does not remount their trees,
  reset filters or initiate provider requests. Settings also subscribes to the
  preference, since `system` and an explicit language can resolve identically.
- `initializeI18n()` runs once in each webview, sets the HTML `lang`, and listens
  for storage and system-language changes. Storage events keep both windows in
  sync. A failed save is reported and the selection still applies to that session.

Provider IDs, quota window labels used for selection, status codes, amounts and
reset timestamps remain data. Translate labels at the rendering boundary using
`localizeLabel`; derive countdowns from timestamps on each render. Never inspect
translated text to choose an action. For example, recovery's `requiresLogin`
field controls the login action in either language.

Use `getLocale()` for `Intl.NumberFormat` and date formatting. Do not construct a
locale-sensitive formatter at module load. Brand names, model IDs, commands,
paths and user-authored session titles stay unchanged. SDK/provider diagnostics
remain verbatim when they are not application-owned messages. Native Rust tray
context-menu copy is outside the React panel catalog.

## Messages that outlive a render

Use `message(key, values)` for events, notifications and asynchronous UI messages;
render them with `renderText`. This keeps parameters separate from translated text
so stored events and pending UI status can follow the current language. Raw
provider diagnostics are strings. Persisted event data is checked at its existing
storage boundary.

Notifications render in the selected language when delivered. Event and
notification deduplication uses the English rendering of the same message, so
changing language does not generate a second alert. Already delivered OS
notifications and historical verbatim diagnostics are not rewritten.

Prefer a complete sentence with interpolation to joining translated fragments.
Do not embed alternate Chinese/English literals in components or return one
language from a helper. No translation service, runtime network request, extra
package, provider migration or compatibility layer is required.

## Verification

`npm test -- --run tests/i18n.test.tsx` covers locale resolution, persistence,
storage synchronization, interpolation, message completeness, provider-state
preservation, quota selection, login recovery and notification deduplication.
Existing UI tests assert the English interface; dedicated i18n tests also exercise
Simplified Chinese. Run `npm test` and `npm run build` for the full frontend gate.
